# What sldr is not

Scope boundaries decided alongside the vision. Each of these is a plausible feature request; the no is deliberate.

1. **Not a hosting or sharing platform.** The deliverable is a self-contained file the user owns. A curation/collaboration platform may exist as a separate product, but it is not part of sldr and is bound by the satellite rules (ADR-0001).
2. **Text-first, forever.** Markdown and plain files remain the canonical authoring surface; visual editing exists only in satellites. This is the price of bitter-lesson resistance — the day editing text becomes the fallback rather than the default, the one-door principle is dead. Visual tools are welcome; they are never primary.
3. **PowerPoint does not define the authoring model.** Markdown/layout/flavor/playlist factoring remains canonical. Export is lossy by design and fidelity is not promised. The core never contains an importer for arbitrary PPTX, and PowerPoint's model never shapes sldr formats. Importing arbitrary decks is agent work — a capable model translating them into canonical slides/layouts/flavors — producing plain files, not a core parser. The one deterministic exception is the bounded round-trip of sldr-generated decks, which is the inverse of the export table and lives in the `sldr-pptx` satellite crate. That round trip is scoped by [ADR-0010](0010-preservation-aware-presentation-interoperability.md); the zone-document model that routes those edits back along provenance is [ADR-0011](0011-zone-document-is-the-editor-and-pptx-model.md). A general Office editor, unrestricted foreign-deck conversion, automatic layout guessing, and silent shared-source edits remain excluded.
4. **No realtime collaboration in the core.** Git is the synchronization and history layer. A satellite may offer live sessions, but it must converge to plain files in git and may never extend core formats to do it.
5. **No embedded intelligence, and no agent orchestration.** The binary makes no model calls, ships no judgment heuristics, and never invokes an agent. Agents use sldr, not the other way round: the agent is a caller of the CLI and the API like any human, and judgment always lives outside the binary. Where determinism stops, sldr hands over a precise, machine-readable residue (a fidelity report, open comments, a translation gap) that any agent can pick up through the same commands; the embedded skill (`sldr skill`) is the handoff. (Amended 2026-09-28: the former `agent` config key, which let sldr shell out to a configured agent, is removed — nothing used it.)

## Supersession

Item 3 is narrowly superseded by accepted [ADR-0010](0010-preservation-aware-presentation-interoperability.md) and furthered by [ADR-0011](0011-zone-document-is-the-editor-and-pptx-model.md), which replaces the earlier unconditional exit-door wording. All other boundaries remain unchanged. Acceptance is scope permission, not evidence of shipped fidelity; consult the [capability contract](../presentation-interoperability.md).
